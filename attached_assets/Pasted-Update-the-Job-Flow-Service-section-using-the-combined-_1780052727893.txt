Update the Job Flow Service section using the combined feedback from the Hygiene Service Manager, Service Admin, and the old ZAP screenshots/videos.

The system must be simple, contract-driven, and easier than ZAP.

CORE PRINCIPLE

Contracts are the source of truth for recurring service work.

A contract must contain:
- the client
- the service type
- the frequency
- the schedule
- the price
- the increase date
- the contract end date
- the route sequence
- the assigned team/technician
- the invoicing rule
- the stock/refill rule

The calendar, daily diaries, technician view, reports, reminders, and client profile must all read from the contract data.

Do not create a separate Service Scheduling main menu item where users manually add duplicate schedule entries.

FIXED TIME

Fixed Time must work like the old ZAP fixed time checkbox.

If Fixed Time = Yes:
The job must appear on the calendar at the selected start time.

If Fixed Time = No:
The job must still appear in the correct route sequence, but the exact time can be treated as flexible.

ROUTE SEQUENCE

Every recurring contract can have a Route Sequence number.

This is especially important for sanitary bins.

Example:
Client: Volkswagen SA
Service Type: Sanitary Bins
Frequency: Monthly
Week of Month: Week 1
Day of Week: Monday
Start Time: 08:00
Route Sequence: 1

The system must show the work in route order.

If Route Sequence is left blank, automatically assign the next available sequence number for that:
- service type
- week of month
- day of week
- assigned team

IMPORTANT DUPLICATE PROTECTION

The old ZAP system sometimes loads the same monthly contract many times in the same month.

Job Flow must prevent this.

Before creating or displaying a contract job occurrence, check for an existing job occurrence with the same:
- contractId
- clientId
- service date
- service type
- assigned team

If one already exists, do not create a duplicate.

If the user tries to create a duplicate, show:
"This contract job already exists for this date."

FINAL GOAL

Job Flow must remove these admin headaches:

- checking contracts ending manually
- checking increase dates manually
- duplicate contract jobs being created
- sanitary bin scheduling in spreadsheets
- stock tracking in spreadsheets
- treatment reports being handled outside the system
- service admin re-entering sales information
- staff not having easy access to current client information

Keep the interface simple.

The basic service workflow must be:

Sales or Admin loads client/job/contract details
Manager/Admin approves contract
Contract stores schedule and frequency
Calendar shows daily technician work
Technician completes job on phone
Treatment report/signature/stock usage saves to client profile
Job becomes ready for invoicing if required
Reports and alerts update automatically
