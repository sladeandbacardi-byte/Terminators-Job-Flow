UPDATE MOBILE JOBFLOW WORKFLOW: FLEETGUARD LOGIN, FIELD DIARY AND ATTENDANCE VEHICLE KM

Make the following changes to the JobFlow mobile user experience.

Do not create duplicate systems.

The goal is to connect:

Attendance
Jobs
Vehicle usage
FleetGuard
Daily activity

into one coherent mobile workflow.

==================================================
1. FIX FLEETGUARD SHORTCUT
==================================================

CURRENT PROBLEM:

A mobile user is already logged into JobFlow.

When they click the FleetGuard shortcut, FleetGuard opens its own login screen again.

This is incorrect.

The user must NOT have to log in twice.

--------------------------------------------------
REQUIRED BEHAVIOUR
--------------------------------------------------

If a mobile user is already authenticated in JobFlow and clicks:

FLEETGUARD

open FleetGuard directly as that same authenticated user.

Use the existing JobFlow session/user identity.

Do not show the FleetGuard login screen again.

The system already knows:

- employee/user
- role
- mobile user identity

Use that information to identify the FleetGuard user.

--------------------------------------------------
SECURITY
--------------------------------------------------

Do not bypass authentication generally.

Only bypass the second FleetGuard login when there is already a valid authenticated JobFlow session.

If there is no valid JobFlow session, the normal login process may still be shown.

Do not expose FleetGuard publicly.

==================================================
2. FIELD DIARIES
==================================================

Review the existing Field Diaries feature.

The current purpose is unclear and it may duplicate:

- Jobs
- Calendar
- Attendance
- Overtime
- Time Off

Do not keep duplicate functionality unnecessarily.

--------------------------------------------------
NEW PURPOSE
--------------------------------------------------

If Field Diaries are retained, convert them into a:

MY DAY / DAILY ACTIVITY

view.

This should NOT require the employee to manually rewrite all their jobs.

Instead, automatically build the day's diary from existing JobFlow records.

Include:

- Attendance Start Work
- Starting vehicle km
- Scheduled jobs
- Completed jobs
- Client/job notes
- Travel where applicable
- Authorised Time Off
- Overtime
- Attendance End Work
- Ending vehicle km
- Total km travelled

The daily diary becomes a timeline of what happened that day.

--------------------------------------------------
IMPORTANT
--------------------------------------------------

Do not require the employee to manually create duplicate diary entries for jobs that already exist in JobFlow.

Automatically populate the diary from existing records.

If the existing Field Diary cannot provide useful functionality beyond this, rename it:

MY DAY

and use it as the consolidated daily timeline.

3. START WORK MUST ASK FOR VEHICLE KM
==================================================

Update Attendance > START WORK.

CURRENT:

Employee presses:
START WORK

JobFlow records the start time.

NEW:

When employee presses:

START WORK

open a small mobile modal BEFORE completing Start Work.

--------------------------------------------------
START WORK MODAL
--------------------------------------------------

Show:

START WORK

Vehicle
[vehicle selector]

Start Vehicle KM
[________]

[ CANCEL ]
[ START WORK ]

--------------------------------------------------
VEHICLE
--------------------------------------------------

If the employee has a normally assigned vehicle, automatically preselect it.

Example:

Garth
JPC031EC - VW Caddy

Allow vehicle selection because employees may occasionally use another vehicle.

Use the existing FleetGuard vehicle database.

DO NOT create another vehicle list.

If the employee selects a different vehicle, record which vehicle was actually used that day.

--------------------------------------------------
START KM
--------------------------------------------------

Start Vehicle KM is REQUIRED if a vehicle is selected.

Numeric input only.

Whole kilometres.

Example:

183420

Display after saving:

183,420 km

Do not allow:

- negative numbers
- letters
- decimals
- obviously invalid values

--------------------------------------------------
FLEETGUARD INTEGRATION
--------------------------------------------------

Where possible, show the latest recorded km for the selected vehicle.

Example:

Last recorded:
183,396 km

The new Start KM must normally be equal to or greater than the previous recorded km.

If lower, show:

"Start km is lower than the vehicle's previous recorded odometer reading."

Prevent submission unless Admin override is used.

4. START WORK SEQUENCE
==================================================

When employee presses START WORK:

1. Show Start Work modal
2. Select/prepopulate vehicle
3. Employee enters Start KM
4. Validate odometer
5. Save Attendance start
6. Save vehicle used
7. Save Start KM
8. Send existing Start Work notification email
9. Update My Day
10. Update FleetGuard vehicle history

The start timestamp must still use SERVER TIME.

Employee must NOT manually choose their Start Work time.

6. END WORK MUST ASK FOR END VEHICLE KM
==================================================

When employee presses:

END WORK

do NOT immediately end attendance.

END WORK

Vehicle:
JPC031EC - VW Caddy

Start KM:
183,420 km

End Vehicle KM:
[________]

[ CANCEL ]
[ END WORK ]

--------------------------------------------------
END KM
--------------------------------------------------

End Vehicle KM is required.

It must be:

greater than or equal to Start Vehicle KM.

Example:

Start:
183,420

End:
183,487

Automatically calculate:

Distance Travelled:
67 km

--------------------------------------------------
VALIDATION
--------------------------------------------------

Reject:

End KM lower than Start KM.

Show:

"End vehicle km cannot be lower than the Start Work odometer reading."

Also flag unusually high daily km.

Example:

If difference is more than a configurable threshold such as 500 km:

"Vehicle travelled 612 km today. Please confirm this reading."

Allow user to confirm if genuinely correct.

Do not automatically reject a legitimate long-distance trip.

9. DO NOT DOUBLE CAPTURE KM
==================================================

Very important:

If Start KM and End KM are captured through Attendance, do not make the employee capture the same odometer readings again in FleetGuard.

The values must be shared.

Attendance Start KM should become a FleetGuard odometer record.

Attendance End KM should become the latest FleetGuard odometer record.

Use ONE source of truth.

10. VEHICLE SWAPPING
==================================================

Employees may use different vehicles.

Record the vehicle actually selected at Start Work.

The End Work screen should default to that same vehicle.

If the employee genuinely changes vehicle during the day, allow:

CHANGE / ADD VEHICLE

Then support multiple vehicle usage segments.

Example:

Vehicle 1:
JPC031EC
183,420 → 183,452
32 km

Vehicle 2:
HDF872EC
221,105 → 221,128
23 km

Total Daily KM:
55 km

Do not build this into the first screen if it makes the normal workflow complicated.

The normal workflow should remain:

one vehicle
one start reading
one end reading

with an optional vehicle-change function.
