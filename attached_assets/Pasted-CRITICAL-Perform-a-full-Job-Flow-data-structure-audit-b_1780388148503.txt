CRITICAL: Perform a full Job Flow data structure audit before adding more features.

The app currently has Sales, Service, Operations, Jobs, Contracts, Calendar, Clients, Quotes and Invoices.

The system must use ONE central client database as the master source of truth.

No module may create or store its own separate version of a client.

MAIN RULE

There must be one central Clients table/collection.

Every lead, quote, job, contract, invoice, treatment report, document, stock usage record and communication note must link back to the central client record using clientId.

Do not duplicate clients in separate Sales, Service, Contract, Job or Invoice data stores.

The clientId must be mandatory for:
- leads
- quotes
- jobs
- contracts
- invoices
- treatment reports
- documents
- communication notes
- stock usage records

SAVE RULE

Do not show "saved successfully" unless the app has completed these checks:

1. The record was saved to the correct database table/collection.
2. The record has a valid id.
3. The record has a valid clientId.
4. The clientId exists in the central Clients database.
5. The saved record can be immediately refetched from the database.
6. The saved record appears in the relevant list/search/profile.

- Jobs list

- Client profile under Jobs
- Search results

DO NOT ALLOW ORPHAN RECORDS

An orphan record is any lead, quote, job, contract, invoice, report, document or stock usage record without a valid clientId.

Do not allow orphan records.

If clientId is missing, block the save and show:
"Please select a valid client before saving."

At no stage may the app create a new duplicate client if a clientId already exists.
