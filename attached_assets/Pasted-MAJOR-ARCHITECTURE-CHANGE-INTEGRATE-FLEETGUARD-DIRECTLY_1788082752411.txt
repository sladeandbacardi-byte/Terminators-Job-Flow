MAJOR ARCHITECTURE CHANGE: INTEGRATE FLEETGUARD DIRECTLY INTO JOBFLOW

CURRENT SITUATION

Terminators currently has:

1. JobFlow
2. FleetGuard

They are separate applications.

JobFlow currently contains a shortcut/link to FleetGuard, but this causes problems because FleetGuard opens separately and has its own login/session.

I no longer want FleetGuard to operate as a separate application from the user's perspective.

JOBFLOW MUST BECOME THE MAIN APPLICATION.

FleetGuard must become an integrated MODULE inside JobFlow.

==================================================
1. TARGET ARCHITECTURE
==================================================

The desired structure is:

JOBFLOW
│
├── Sales
├── Service
├── Finance
├── Operations
│   ├── HR
│   ├── Attendance
│   ├── Time & Overtime

└── Reports

FleetGuard should now live under:

Operations > Fleet

Do not send the user to a separate FleetGuard application.

21. MIGRATION SAFETY
==================================================

IMPORTANT:

Do not immediately delete or disable the standalone FleetGuard application.

Migration sequence:

PHASE 1
Identify FleetGuard functionality and database dependencies.

PHASE 2
Build Fleet module inside JobFlow.

PHASE 3
Connect/migrate existing FleetGuard data.

PHASE 4
Test all Fleet functions inside JobFlow.

PHASE 5
Run JobFlow and old FleetGuard in parallel temporarily.

PHASE 6
Confirm data and functionality.

PHASE 7
Only then retire the standalone FleetGuard interface.

Do NOT risk losing existing production FleetGuard data.
