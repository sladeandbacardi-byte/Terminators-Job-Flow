Do not require the user to click an extra Sign In button after selecting their name.

Current problem:
The user clicks their name, then still has to click Sign In. This is unnecessary.

- Staff Login
- Admin Login

4. Remove Sign In button from user selection screens

The Sign In button can be removed or hidden for now.

5. Future Password/PIN Support

Design the code so passwords/PINs can be added later.

Add a future-ready setting:

authMode:
- quickLogin
- pinLogin
- passwordLogin

For now use:

authMode = quickLogin

In quickLogin mode:
Clicking a user logs in immediately.

Later, when authMode is changed to pinLogin or passwordLogin:
Clicking a user should open a PIN/password screen.

But do not require PIN or password now.

6. Session Handling

After user clicks their name:
- Save logged-in user to localStorage/sessionStorage
- Save user role
- Save user type: staff or admin
- Route to correct dashboard

Refreshing the page should keep the user logged in unless they click Switch User / Logout.

7. Switch User

Keep a Switch User / Logout option in the header/menu.

Clicking Switch User should:
- Clear current user/session
- Return to the main login screen

8. Back Navigation

Staff Login screen must have:
Back to Main Login

Admin Login screen must have:
Back to Main Login
