Fix the Sales Diary drag-and-drop and appointment label display.

The current diary drag-and-drop is not working properly, and the appointment labels are not good enough.

The Sales Diary must behave like Microsoft Outlook Calendar.

MAIN REQUIREMENTS:

1. Drag-and-drop must work
Users must be able to drag appointments:
- To another time on the same day
- To another day in week view
- To another user in Team View
- To another date in month view

When an appointment is dropped:
- Update date
- Update startTime
- Update endTime
- Preserve the same duration
- Update assignedUserId if moved to another user in Team View
- Save immediately to the database

If saving fails:
- Move the appointment back to its original position
- Show the actual error message

Do not show only:
"Could not update appointment."

Show:
"Could not move appointment: [actual reason]"

2. Resize must work
Users must be able to resize an appointment by dragging the bottom edge.

Example:
09:00–10:00 dragged down to 12:00 becomes:
09:00–12:00

Save the new endTime and calculated duration.

3. Use Outlook-style time logic
Source of truth:
- date
- startTime
- endTime

Do not use fixed 60-minute height.
Do not use estimated duration as source of truth.

Calendar block position:
top = minutesSinceCalendarStart(startTime) * pixelsPerMinute

Calendar block height:
height = minutesBetween(startTime, endTime) * pixelsPerMinute

Examples:
08:00–08:30 = 30-minute block
09:00–10:00 = 1-hour block
11:30–16:30 = 5-hour block
09:00–15:00 = 6-hour block

4. Snap drag and resize to 15-minute intervals
Allowed time increments:
- 08:00
- 08:15
- 08:30
- 08:45
- 09:00

5. Fix appointment labels

The current labels are too cramped and unclear.

Use Outlook-style appointment display.

MONTH VIEW LABEL:
In month view, show appointments as compact horizontal bars.

Format:
Time Client / Subject

Examples:
07:30 Preventive Maintenance Plan
09:00 Blue Waters Hotel
11:30 Site Visit - Greenacres Medical Centre

If the appointment is all day or very long, show:
Blue Waters Hotel - Site Visit

Do not show bulky cards in month view.
Do not show confusing clipped labels like:
"07:..."
"3h ..."
"08:..."
"1h ..."

6. WEEK/DAY VIEW LABEL:
In week/day view, the appointment block must show:

For blocks with enough space:
Client / Lead Name
Appointment Type
09:00–15:00 · 6h
Status

Example:
Blue Waters Hotel
Site Visit
11:30–16:30 · 5h
Confirmed

For smaller blocks:
Blue Waters Hotel
11:30–12:00

For very small blocks:
11:30 Blue Waters

Label priority:
1. Time
2. Client / lead / company name
3. Appointment type
4. Status
5. Duration

Never hide the time completely.
Never show only duration without the client/appointment name.

7. Appointment title logic
The appointment title should be generated cleanly.

Use this priority:
- If linked client exists: client name
- Else if linked lead exists: lead company name
- Else use appointment title
- Else use appointment type

Display label should combine:
Client/Lead Name + Appointment Type

Examples:
Blue Waters Hotel - Site Visit
Greenacres Medical Centre - Quote Follow-up
Internal Sales Meeting
Fuel Price
Preventive Maintenance Plan

- Client / lead name
- Appointment type
- Date
- Start time
- End time
- Duration
- Assigned user
- Contact person
- Phone
- Site address
- Status
- Notes

9. Click to edit
Clicking an appointment must open the edit appointment modal.

10. Use users, not separate sales reps
Sales reps must be JobFlow users.

Assigned user dropdown must use active users with:
- Sales Rep
- Sales Admin
- Manager
- Admin
or sales permission.

Do not use a separate sales rep table unless it is directly linked to users.

11. Team View
Team View must show appointments grouped by assigned user.

Dragging an appointment from one user to another must update:
assignedUserId

12. API update route
Ensure drag/drop and resize use the same reliable update endpoint.

Preferred:
PATCH /api/sales-appointments/:id

Payload for moving:
{
  "date": "2026-07-08",
  "startTime": "09:00",
  "endTime": "14:00",
  "assignedUserId": "user-id"
}

Payload for resizing:
{
  "endTime": "12:00"
}

Backend must validate:
- appointment exists
- user has permission
- date is valid
- startTime is valid
- endTime is valid
- endTime is after startTime
- assignedUserId is valid

- drag-and-drop
