URGENT FIX: WRONG DATABASE URL CAUSING RAILWAY CRASH

The Railway deploy logs show this error:

AggregateError [ECONNREFUSED]
_url: 'wss://postgres.railway.internal/v2'
code: 'ECONNREFUSED'

This means the app is trying to connect to Postgres using:
wss://postgres.railway.internal/v2

That is not a valid normal Postgres DATABASE_URL for Drizzle/Node Postgres.

Fix the database configuration.

1. Find where the app reads DATABASE_URL or POSTGRES_URL.

2. Make sure the backend database client only uses a normal Postgres connection string:
postgresql://...
or
postgres://...

3. Do not use:
wss://postgres.railway.internal/v2

4. Check Railway Variables for the Terminators-Job-Flow service.

The app should have:
DATABASE_URL=${{Postgres.DATABASE_URL}}

or use the actual Postgres connection string from the Railway Postgres service.

It must not use the Railway internal WebSocket URL.

5. In the database connection file, add validation:

If DATABASE_URL starts with "wss://", throw a clear startup error:
"Invalid DATABASE_URL: expected postgres:// or postgresql://, received wss://"

But do not let login endpoints crash repeatedly. Log the issue clearly.

6. Update Drizzle/database config to use:

process.env.DATABASE_URL

Example:

import postgres from "postgres";

const connectionString = process.env.DATABASE_URL;

if (!connectionString) {
  throw new Error("DATABASE_URL is missing");
}

if (!connectionString.startsWith("postgres://") && !connectionString.startsWith("postgresql://")) {
  throw new Error("Invalid DATABASE_URL. Expected postgres:// or postgresql://");
}

export const client = postgres(connectionString, {
  ssl: process.env.NODE_ENV === "production" ? "require" : false,
});

7. Check drizzle.config.ts also uses the same DATABASE_URL:

dbCredentials: {
  url: process.env.DATABASE_URL!,
}

8. Remove any use of:
RAILWAY_TCP_PROXY_DOMAIN
RAILWAY_PRIVATE_DOMAIN
postgres.railway.internal
wss://postgres.railway.internal/v2

unless it is specifically for Railway internal tooling. It must not be used as DATABASE_URL.

9. After fixing code, update Railway Variables:
DATABASE_URL must point to the Postgres plugin connection string.

10. Redeploy.
