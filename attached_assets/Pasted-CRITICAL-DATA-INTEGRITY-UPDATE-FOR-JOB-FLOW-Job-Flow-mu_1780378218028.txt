CRITICAL DATA INTEGRITY UPDATE FOR JOB FLOW

Job Flow must have ONE central client/customer database.

This is extremely important.

There must not be separate client records for Sales, Service, Contracts, Jobs, Quotes, or Finance.

The client/customer database must be the main source of truth for all client information in the app.

MAIN RULE

Create and enforce one central Clients/Customers table/collection.

Every lead, quote, job, contract, invoice, treatment report, stock usage record, document, and communication note must link back to one clientId from the central Clients/Customers database.

Do not duplicate client information into separate modules.

Do not create separate customer records inside:
- Sales
- Leads
- Quotes
- Jobs
- Contracts
- Invoices
- Service Scheduling
- Daily Diaries
- Reports

All modules must reference the same clientId.

RELATIONSHIP STRUCTURE

Use this relationship model:

Client has many Leads.
Client has many Quotes.
Client has many Jobs.
Client has many Contracts.
Client has many Invoices.
Client has many Treatment Reports.
Client has many Documents.
Client has many Communication Notes.
Client has many Stock Usage Records.

Every related record must store:
- clientId
- clientName snapshot optional
- createdAt
- updatedAt

The clientId is mandatory.

The clientName snapshot is only for display/history and must not replace the clientId.

CONVERT FLOW

The conversion flow must preserve the same clientId at every step.

Use this flow:

Lead
↓
Quote
↓
Job
↓
Contract if recurring
↓
Invoice

At no stage may the app create a second client record if a clientId already exists.

When converting:
- lead to quote
- quote to job
- job to contract
- job to invoice
- contract to invoice

the app must carry forward the same clientId.

DATA VALIDATION

Before saving any lead, quote, job, contract, invoice, report, or document:

1. Check that clientId exists.
2. Check that the clientId belongs to a real client in the central Clients database.
3. If clientId is missing, do not save.
4. Show this error:
"Please select a valid client before saving."

Do not allow orphan records.

An orphan record means a job, contract, quote, invoice, or document without a valid clientId.

This must not be allowed.

SAVE CONFIRMATION RULE

Do not show "saved successfully" unless:

1. The record was saved to the correct database table/collection.
2. The record has a valid id.
3. The record has a valid clientId.
4. The app can immediately refetch the saved record.
5. The saved record appears in the correct list/search/profile.

After saving a contract, the app must confirm it appears in:
- Contracts list
- Client profile under Contracts
- Contract search results
- Schedule View if active
- Calendar if scheduled

After saving a job, the app must confirm it appears in:
- Jobs list
- Client profile under Jobs
- Job search results
- Calendar if scheduled
- Daily Diary for the correct date
